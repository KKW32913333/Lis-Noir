# Lis Noir（リス・ノワール）

## 概要

| 項目 | 内容 |
|---|---|
| ジャンル | ターン制カードバトル |
| プラットフォーム | Webブラウザ / PWA（iOS・Androidのホーム画面に追加可能） |

## 主な特徴

- **属性の三すくみ**：火→自然→水→火のジャンケン関係に加え、光と闇はお互いが弱点という独自バランス
- **リーダースキル＋アルティメットスキル**：常時発動する永続バフに加え、5ターンごとに使える強力な全体攻撃を搭載
- **絆レベル**：同じカードを繰り返し入手すると称号・演出が変化する、コレクションのやり込み要素
- **オートバトル・バトル倍速**：周回プレイを快適にする自動戦闘・2倍速モード
- **相棒ドラゴン育成**：エサをあげて育成し、レベルに応じてバトル開始時の最大HPが上昇する育成コンテンツ
- **ログインボーナスカレンダー**：7日周期で報酬が変化する継続プレイ施策
- **体験型チュートリアル**：実際の画面を操作しながら遊び方を学べる、スポットライト方式のガイド
- **排出確率の開示**：各ガチャのカード1枚ごとの正確な排出確率を確認可能（ストア審査基準への対応）
- **クラウド保存**：メールアドレスでログインすると、機種変更後もデータを復元可能

## ゲームシステム

### バトル

- ターン制。毎ターン、上限まで回復する「コスト」を消費して手札のカードを使用する
- 手札のカードをタップして選択→自分の場の空きマスをタップで召喚、攻撃可能なモンスター（緑の点つき）をタップ→敵モンスターか、敵の顔アイコン／画面下の「直接攻撃」ボタンをタップで攻撃
- 属性相性（三すくみ・光闇）により、攻撃力にダメージ補正がかかる
- 自分のターン開始時、「カードを引くかどうか」を選択可能（引きすぎによる手札あふれを回避できる）。敵AIも同様の判断を行う
- 状態異常（継続ダメージ・行動不能）、シールドなど、カード固有スキルによる多彩な効果
- **オートバトル（AUTO）**：敵AIと同様のロジックで、カードの使用・攻撃・ターン終了を自動化
- **バトル速度（1x/2x）**：演出・待ち時間を短縮し、周回プレイのテンポを上げる

### カード

- レア度：ノーマル／レア／エピック／レジェンドの4段階（レジェンドはカード自体が虹色に光る演出つき）
- カード種別：モンスター（アタッカー／ディフェンダー）、スペル、装備、フィールド
- **絆レベル**：同じカードを繰り返し入手すると称号バッジが表示され、最高段階では金色に光る演出が追加される（能力値には影響しない、見た目のみのやり込み要素）
- カード図鑑（カード一覧画面）で、所持・未所持を含めた全カードの詳細を確認可能。属性・タイプ別の絞り込み、並び替えにも対応

### デッキ編成

- カード一覧からタップしてデッキに追加、デッキ内カードは左上の「−」ボタンでその場から取り外し可能（コレクションとデッキを行き来せず編成できる設計）
- デッキシナジー表示：属性バランス・アタッカー/ディフェンダー比率を可視化し、初心者でも組みやすいアドバイスを表示
- デッキプリセット（複数デッキの保存・切り替え）、自動編成機能に対応
- **デッキ共有コード**：自分のデッキ構成をコード化して発行し、フレンドに送って見てもらえる（読み取り専用）

### リーダー

7人のリーダーから1人を選択して出撃する。ガチャは不要で、全員いつでも選択可能。

| 属性 | 特徴 |
|---|---|
| 闇 | エレナ・ノワール／ディアブロ・ノワール |
| 光 | テスタ・ブラン／ジュード・ブラン |
| 水 | リーラ・マリーン |
| 火 | エル・カイエン |
| 自然 | モナ・ロマネスク |

- **リーダースキル**：対応属性の味方モンスターを永続的に強化する、常時発動の受動効果
- **アルティメットスキル**：バトル中5ターンごとに使用できる、敵本体・敵の場全体への強力な攻撃＋固有の追加効果。自分のアイコン下の「◯/5」で準備状況を確認でき、タップで発動、長押しで詳細情報を表示

### ガチャ

| ガチャ名 | 消費 | 特徴 |
|---|---|---|
| 初心者ガチャ | 💎（初回無料） | 全プレイヤーが最初に必ず引くガチャ。以降も通常ガチャとして継続利用可能（50連以内にレジェンド確定） |
| ノーマルガチャ | 💎 | ノーマル・レアのみ排出 |
| プレミアムガチャ第1弾 | 💎 | レア〜レジェンドを排出（50連以内にレジェンド確定） |
| 期間限定ガチャ（2種） | 🎫期間限定チケット | 収録カードから確定で1体排出。チケットは共通で、どちらのガチャにも使用可能 |

- 各ガチャに「📊排出確率を見る」から、カード1枚ごとの正確な排出確率を表示（レア度内の候補カード数に関わらず、表示通りの確率で抽選される仕組み）
- 天井（保証）システムにより、一定回数ノーマルのみが続くと次回はレア以上が確定

### ステージ・ダンジョン・クエスト

- **ストーリー**：全10ワールド・50ステージ。初回ステージにはストーリー演出つき。敵デッキのレジェンドカード枚数はワールド進行度に応じて上限が設けられている（序盤1枚まで→ラスト4枚まで）
- **ダンジョン**：全100階。10階ごとにボスフロアが出現し、専用の伝説装備を入手できる階も存在。到達階層の表示をタップすると、その階から直接プレイ可能
- **高難易度クエスト**：属性ごとの強敵に挑む6種のクエスト
- **特別クエスト**：ストーリーとは異なる特別な強敵に挑む3種のクエスト

### ランク・ランキング

- 勝敗に応じてトロフィーが増減し、ブロンズ→シルバー→ゴールド→プラチナ→ダイヤモンドの5段階でランクが変動
- 月次でシーズンリセット
- クラウド連携時、全プレイヤーのランキングを閲覧可能

### 育成・やり込み要素

- **ミッション**：多数のミッションを達成すると報酬を獲得（まとめて受け取りにも対応）
- **ログインボーナスカレンダー**：7日周期。連続ログインで進み、間が空くと1日目からやり直し。7日目のみ報酬が多め
- **プレゼントボックス**：ウェルカムボーナス等の受け取り
- **図鑑コンプリート報酬**：全カード収集で特別報酬
- **相棒ドラゴン育成**：ゴールドでエサをあげて育成。卵→幼竜→若竜→成竜→古代竜と成長し、レベルに応じてバトル開始時の最大HPが上昇する（ホーム画面のクイックメニュー「ドラゴン」からアクセス）

### オンライン対戦（β）

フレンドと合言葉コードで部屋を作り、実際のデッキ・リーダーで対戦できる機能。ターン制で、自分のターン中のみ操作可能（相手のターン中は待機表示）。カード使用・攻撃・アルティメットスキルなどの行動をリアルタイムに同期し、どちらかのHPが0になった時点で勝敗が決定します。現時点ではβ版（試験提供）で、カードを引くかどうかの選択機能・切断時の処理など、一部は今後の改善予定です。Firebase側の実装内容は [`ONLINE_BATTLE_FIREBASE_SPEC.md`](./ONLINE_BATTLE_FIREBASE_SPEC.md) を参照してください。

### チュートリアル

- 初回プレイ時、スライド形式の導入案内に続けて、**実際の画面を操作しながら学べる体験型チュートリアル**が始まる
- 画面の該当箇所が光る「スポットライト」演出で、タップすべき場所を直感的に案内
- 設定画面の「遊び方をもう一度見る」から、いつでも再視聴可能

### 設定・データ管理

- 効果音・BGM（音量調整可）のON/OFF
- **クラウド保存**：メールアドレスでログインすると、進行状況が自動でクラウドに同期され、機種変更後も復元可能
- 各画面右上の「？」ボタンから、その画面の詳しい遊び方をいつでも確認可能

## 技術構成

- **フロントエンド**：Vanilla HTML / CSS / JavaScript（フレームワーク不使用）
- **PWA**：Service Worker（`sw.js`）によるオフラインキャッシュ対応。アプリ起動時・前面復帰時に自動で新資材をチェックし、更新があれば自動反映
- **バックエンド**：Firebase（Authentication・Firestore）によるクラウド保存・ランキング機能（`firebase-init.js`、非公開）
- **ホスティング**：GitHub Pages 等の静的ホスティングを想定

## 既知の制限事項

- **`firebase-init.js`は編集・動作確認の対象外**：クラウド保存・ランキング・オンライン対戦の同期処理はこのファイルに依存しており、Firebase側の実装・動作確認は別途行う必要があります
- **オンライン対戦は現時点でβ版**：対戦自体は可能ですが、カードを引くかどうかの選択機能の省略、切断時の処理など、一部は今後の改善予定です
- **セーブデータは端末のブラウザに保存**：クラウド保存を利用しない場合、ブラウザのキャッシュ削除等でデータが失われる可能性があります
- **iOSアプリ化には追加対応が必要**：現状はPWAとして提供されており、App Storeでの配信にはネイティブラッパー化（Capacitor等）・審査対応・課金システムの実装が別途必要です

## 開発・保守に関する補足

- カードやガチャなどのデータは `cg-game.js` 内の定数（`CARD_DEFS` / `SHOP_PACKS` / `STAGES` など）にまとまっています
- カードを削除する際は、ボスカードやガチャの収録リストなど、他の参照箇所との整合性の確認が必要です（既存の仕組みにより、削除済みカードは所持データ・デッキから自動的に除去されます）
- Service Workerのキャッシュを更新する際は、`sw.js`内の`CACHE_NAME`のバージョン番号を必ず更新してください（更新しないと、資材の変更が反映されません）

### 直近セッションの詳細記録

- **バトル画面のUI改善**：直接攻撃ボタンの新設・移動、山札/手札/墓地表示の絵文字→通常表記化、行動不能の説明追加、カードを引くかどうかの選択制導入（敵AIも判断するよう対応）
- **発熱対策**：画面・ポップアップが非表示後も裏側で描画され続けていた問題を特定し、`display:none`化による対策を実施。レジェンド/エピックカードの光沢演出（虹色シャイン）を、負荷の高い`background-position`アニメーションから、GPU負荷の低い`transform`ベースの実装に作り直し
- **デッキ編成の改善**：カードコレクションからの「−」ボタンによるその場での取り外し、デッキシナジー表示（属性バランス・役割比率の可視化とアドバイス）、デッキ共有コード機能を実装
- **オートバトル・バトル倍速**：周回プレイ向けに、敵AIと同ロジックで自動進行するオートバトル、演出短縮の倍速モードを実装。オートバトル中にアルティメットスキルが使われない不具合も修正

- **バトルリプレイ／戦績詳細**：対戦中の主要行動（カード使用・攻撃・アルティメットスキル）をログとして記録し、対戦履歴から振り返れる機能を実装
- **絆レベル**：カードの累計入手数に応じて称号・光る演出が変化する、能力値に影響しないコレクション要素を実装
- **ガチャ排出確率の適正化と開示**：レア度内のカード候補数によって実際の排出率が表示と食い違っていた不具合を発見・修正し、カード1枚ごとの正確な確率を表示する機能を追加（ストア審査基準への対応）
- **カードデータの複数回にわたる調整**：フレイムスライム・スピリットメイデン・シャドウアサシン・シャドウバット等のレア度変更、リーフバード→シルフの名称・画像変更、世界樹の守護者の削除、炎龍王クリムゾンの「ガチャ対象外の初期配布モンスター」化、聖騎士アークガーディアン等6種の完全削除とボスカード参照の再編成
- **チュートリアルの刷新**：読むだけのスライド形式から、実際の画面を操作しながら学べる体験型チュートリアルへ全面的に作り直し。開発中に見つかった「対象要素の再描画でタップ判定が効かなくなる」不具合を、クリック時にその場のデータで判定する方式に設計し直すことで解消
- **オンライン対戦（β）の土台構築**：合言葉コードによる部屋作成・参加のゲーム側実装、および必要なFirebase側の実装仕様書（`ONLINE_BATTLE_FIREBASE_SPEC.md`）を作成
- **iOSアプリ化に向けた準備**：ガチャ確率表示（審査基準対応）、プライバシーポリシーのドラフト作成
- **資材更新の自動反映**：アプリ起動時・前面復帰時に新資材を自動チェックし、更新があれば自動でページを再読み込みする仕組みを実装（手動でのアプリ削除・キャッシュクリアを不要にするための対応）
- **READMEの全面刷新**：更新履歴の羅列形式から、プロジェクトの現状を体系的に説明する構成へ作り直し（本セクションとして、それまでの更新履歴も保持）
- **オンライン対戦（β）：firebase-init.jsの実装完了**：これまで仕様書のみだった7つの関数（`createBattleRoom`／`joinBattleRoom`／`listenToBattleRoom`／`listenToBattleActions`／`submitBattleAction`／`finishBattleRoom`／`leaveBattleRoom`）を実装。あわせて匿名ログイン機能（`signInAnon`）を追加し、メール登録なしでも対戦できるようにした。対応するFirestoreセキュリティルールを`FIRESTORE_RULES_ONLINE_BATTLE.md`にまとめて提供
- **オンライン対戦の不具合修正**：「コードで参加する」実行時に「ログインに失敗しました」と表示される事象を調査。原因はFirebaseコンソールで匿名ログインが未有効化の場合に発生するもので、あわせて、実際のエラー内容が握りつぶされて汎用メッセージしか出ない実装になっていたため、具体的な理由が画面に表示されるよう修正
- **体験型チュートリアルの開始タイミングを修正**：初心者ガチャを引いた直後、カードの獲得演出（開封アニメーション・カード獲得ポップアップ）が表示されている裏側で、体験型チュートリアルが同時に始まってしまう不具合を修正。原因は、チュートリアルの開始条件をホーム画面の再描画に紐付けていたため、購入直後（演出が始まる前）に条件を満たしてしまっていたこと。カード獲得ポップアップを実際に閉じたタイミングを開始条件とするよう修正し、演出を最後まで見てからチュートリアルが始まるようにした

- **ストーリーの最終ステージ（50）をクリアしても「クリア済み」と表示されない不具合を修正**：進行度の上限がステージ数（50）に固定されており、最終ステージだけはクリアしても進行度が加算されず、「クリア済み」の判定条件を満たせない仕組みになっていた。他のステージと同様に、最終ステージクリア時も進行度が1つ先に進むよう修正。既にクリア済みなのに表示がおかしいままの既存プレイヤーについても、対戦履歴から自動判定して修正する仕組みを追加
- **ストーリークエストの報酬（ゴールド・ジェム）の上がり幅を縮小**：ステージが進むごとの増加ペースが急すぎたため（最終的に開始時の約100倍まで増加）、なだらかなカーブに調整。最終ステージの報酬も、ゴールド8,000→2,200、ジェム800→220に縮小し、ステージ間の増加幅も大きな段差がないよう平滑化
- **ストーリークエストの敵HP上限を450→500に変更**：あわせて、以前は36ステージ目以降がすべて同じHP（450）で頭打ちになっていたのを解消し、最終ステージ（50）まで緩やかに増加し続けるカーブに再設計
- **「炎龍王クリムゾン」の入手方法を変更**：これまでゲーム開始時に勝手にカードコレクションへ追加されていたが、プレゼントボックスから受け取る方式に変更。プレゼント画面から任意のタイミングで受け取れるようになった
- **ミッション画面の「まとめて受け取る」ボタンとカテゴリタブの余白を拡大**：ボタンとタブが近すぎて重なって見える問題があったため、余白を広げて調整

- **クラウド保存後、アプリを完全に終了して再起動すると復元できない不具合を修正**：原因は2つありました。①クラウドのデータが見つかった際の「復元しますか？」という確認が、標準ブラウザ機能の`confirm()`を使っていたが、これはホーム画面に追加したスタンドアロンPWAでは正しく動作しないことがあり、誤って「いいえ」相当の扱いになると、復元されないどころか端末側の空のデータでクラウドを上書きしてしまう危険があった。バックアップコードからの復元機能も同様の作りだった。②ログインセッションが端末に残っていても、端末内のセーブデータ自体が消えてしまっていた場合に、自動でクラウドとの差分に気づいて復元を提案する仕組みがなかった
- 対応として、確実に表示される専用の確認画面に置き換え、あわせてログイン状態が保持されているのに端末のデータが初期状態に見える場合は、自動でクラウドのデータを検知し復元を提案するようにした。シミュレーション環境で、ログインからの復元・バックアップコードからの復元・自動検知による復元提案のすべてを確認済み
- なお、iOSのスタンドアロンPWA（ホーム画面追加アプリ）は、一定期間操作がないと端末内のデータが消去されることがある仕様上の制約があるため、根本的な予防策としては、こまめな設定画面からのクラウド同期・定期的なバックアップコードの保存を引き続きおすすめします

### 追加修正：体験型チュートリアルの画面固まりが再発していた件

前回の修正（古いスポットライトを即座に非表示にする対応）後も、実機で同じ症状が再発するとのご報告を受け、より深く調査しました。

**実際の原因**：スポットライトには「再描画で対象の位置がずれても追従できるよう、表示中は0.4秒ごとに位置を再計算し続ける」仕組みがありました。ステップが完了してタップ対象が切り替わった際、前回の修正で古いスポットライトを**即座に非表示にする**対応はしていたものの、この「0.4秒ごとに位置を再計算し続ける」タイマー自体は止めていませんでした。そのため、非表示にした直後、このタイマーが1回だけ働いてしまい、古い対象（例：カードタブ）を囲むスポットライトを**復活させてしまう**ことがありました。このタイミングで画面がすでに切り替わっていると、復活したスポットライトが新しい画面をブロックし、「固まったように見える」不具合につながっていました。

**修正**：ステップが完了した瞬間に、この再計算タイマーそのものを確実に停止するよう修正しました。実機での再発個所（カードタブ→カード編成画面）と同じ状況を再現するテストを行い、タイマーが復活しないこと、全7ステップが最後まで正しく完了することを確認済みです。

### 追加修正：アプリを完全に終了するたびに、チュートリアルの再表示・データの消失が起きる件

「アプリを落とすたびにチュートリアルが開始される」「データが消えてしまう」というのは、実は同じ原因（端末内の保存データが読み込めていない）による、1つの問題の2つの現れ方です。

**見直した点①**：前回、資材更新を自動反映させるために「Service Workerが更新されたら自動でページを再読み込みする」処理を追加していましたが、この自動再読み込みが、意図しないタイミングで発生し、アプリのセッション継続に影響を与えていた可能性があったため、この自動再読み込みは取りやめました（新しい資材は、次にアプリを開き直した際に自然に反映されます）。

**見直した点②**：アプリが裏に回る・閉じられる直前に、念のため確実に最新のデータを保存し直す仕組みを追加しました。何らかの理由でこまめな保存のタイミングを逃していた場合でも、アプリを閉じる直前に必ず保存されるようにするための保険です。

なお、iOS（Safari）のホーム画面追加アプリには、端末内のデータが消去されることがあるという仕様上の制約が存在することも分かっています。今回の対応で改善が見込めますが、万一のデータ消失に備えて、設定画面の「クラウド保存」機能へのログイン（無料）を強くおすすめします。ログインしておけば、端末側のデータが万一消えてしまっても、次に開いた際に自動でクラウドのデータの復元が提案されます。

### 追加調査：アプリを完全に終了するたびにデータが消える件（既存プレイヤーでも発生）

改めて詳しく調査しました。iOSのSafari経由でホーム画面に追加したPWAでは、**端末内のデータ（localStorage）が予告なく消去されることがある**という、開発者コミュニティでも広く報告されている既知の仕様上の制約があることを、複数の一次情報で確認しました。ホーム画面に追加したアプリはこの制約の対象外とする、というWebKit側の方針もあるようですが、実際には対象外にならないケースが多数報告されており、Appleからの明確なドキュメントもない状態です。

**対応した点**：
- 端末のストレージ容量が厳しい場面などで、このアプリのデータが優先的に消去されないよう、ブラウザに「永続化ストレージ」を要求する処理を追加しました（`navigator.storage.persist()`。保証されるものではありませんが、有効な対策として知られている標準機能です）
- クラウド保存にログインしていない状態で、ある程度プレイが進んでいる場合に、ホーム画面で「クラウド保存の設定をおすすめします」というバナーを表示するようにしました（閉じることも可能です）。前回・前々回の対応で、クラウド保存にログインしてさえいれば、端末のデータが消えても自動で復元を提案する仕組みは既に整っているため、このバナーを通じてログインを済ませていただくことが、実質的に最も確実な対策になります

**正直なところ**：この問題は、コード側の対応だけで100%防げる性質のものではなく、Apple／WebKit側の仕様に起因する部分が大きいことが分かっています。今回の対応で改善が期待できますが、**クラウド保存へのログインが、データを守るための最も確実な方法**であることに変わりはありません。

### オンライン対戦（β）の対戦部分を実装

これまで「部屋を作る・参加する（マッチング）」までしか実装できていませんでしたが、**相手が見つかった後、実際に対戦できる部分**を実装しました。

**仕組み**：お互いの端末はターン制で行動し、自分の操作（カードの使用・攻撃・アルティメットスキル・ターン終了など）をクラウド経由で相手の端末に伝え、相手の画面にも同じように反映されます。実装の途中、攻撃やカードの使用には非常に多くの固有スキルパターン（10種類以上）があり、さらに一部にはランダム要素（ランダムな相手を攻撃する等）を含むカードもあることが分かりました。単純に「相手が攻撃した」という情報だけを送って各端末が個別に結果を計算する方式だと、ランダム要素によって両者の画面が食い違ってしまう（同期がずれてしまう）リスクがあったため、**行動の結果が確定した状態そのものを送る方式**に設計し直し、両端末で必ず同じ結果になるようにしました。

- 自分のターン中のみ操作可能。相手のターン中は「⏳相手のターンです…」と表示され、操作がブロックされます
- カードは毎ターン自動的に1枚引かれます（v1として簡略化。カードを引くかどうかの選択機能は今後の対応とします）

### クラウドデータが誤って上書きされる不具合を修正

ご報告いただいた「資材入れ替え後にログインしたら、データが上書きされて初めからになってしまった」件について調査し、原因となる仕組みを2箇所発見・修正しました。

**原因①：ログイン時の選択肢の表現が誤解を招いていた**：ログイン時に「クラウドにセーブデータが見つかりました」と表示され、「この端末のデータのままにする」を選ぶと、実は**クラウド側のデータがこの端末のデータで上書きされて消えてしまう**仕組みでした。「そのままにする」という表現から、何も変更されない安全な選択のように見えてしまい、実際にはクラウドの進行状況を失ってしまう危険な操作だったことが分かりました。

**原因②：この端末に古いデータが残っている場合、確認なしにクラウドへ同期されていた**：この端末に一度でも「初回ガチャ済み」の記録があると、クラウド側の方が大幅に進行していても、確認なしにそのまま通常のプレイが始まり、やがて自動同期によってクラウド側の進んだデータが、この端末の古いデータで上書きされてしまう可能性がありました。

**対応内容**：
- ログイン時、「この端末」と「クラウド」それぞれのレベル・トロフィー・ステージ進行度・所持カード数を比較表示するようにしました
- 「この端末のデータを使う」を選んだ場合、クラウドのデータが完全に失われる旨を明記した警告と、取り消せない操作であることを踏まえたもう一段階の最終確認を追加しました
- ログイン時、この端末に古い進行データが残っている状態でも、クラウド側が大幅に進んでいる場合は、自動で上書きせず、同様の比較画面で確認を求めるようにしました（トロフィー差500以上、またはステージ進行差3以上を目安に判定）

なお、通常通りの同期（両者の進行状況に大きな差がない場合）では、これまで通り確認なしでスムーズに進みます。ご質問いただいた「資材入れ替え前にログアウトしておく」という対策も、有効な回避策の一つです（ログアウトしていれば、そもそも自動同期は行われません）が、今回の修正により、ログインしたままの状態でも安全性が高まっているはずです。

### 【重大な不具合修正】チュートリアルが進行しない問題と、その根本原因（初期デッキが3枚しか組まれない不具合）

ご指摘のチュートリアル不具合を調査したところ、チュートリアル自体の不具合というより、**もっと根深い不具合**が原因だと分かりました。

**発見した根本原因**：新規プレイヤーの初期デッキを自動生成する仕組み（`buildStarterDeck()`）が、「プレミアムガチャ・初心者ガチャ限定カードは初期デッキに含めない」という除外リスト（`BEGINNER_GACHA_CARD_IDS`）を参照する設計になっていました。これまでのセッションで新しいノーマル・レアカードを追加するたびに、正しく「ガチャ限定」としてこの除外リストへ登録してきたのですが、その結果、初期デッキに使えるカードの候補が段々減っていき、**最終的に候補が「俊足のウサギ」1種類だけになってしまい、20枚組むはずの初期デッキが3枚しか生成されない状態**になっていました。新規プレイヤーは所持カードも初期デッキの内容とイコールになる仕組みのため、所持カードもこの1種類だけという状態でした。

この状態では、チュートリアルの「カード一覧からカードをタップしてデッキに追加してみましょう」というステップが、"まだデッキに入っていないカード"を探しても見つからず（所持している唯一のカードは、既に初期デッキで上限の3枚まで入っていたため）、進行が止まってしまっていました。

**対応した修正**：
1. 初期デッキ専用の固定候補リスト（`STARTER_DECK_CANDIDATE_IDS`、全属性から2種ずつ計10種類）を新設し、今後どれだけガチャ限定カードを追加しても初期デッキの候補が先細りしないようにしました
2. チュートリアルの「カードをデッキに追加」ステップの判定条件も、「デッキに0枚のカード」ではなく「まだ上限枚数（3枚）に達していないカード」に修正し、実際のカード追加の仕組みと一致させました

これにより、新規プレイヤーは20枚の初期デッキ・10種類の所持カードでゲームを開始できるようになり、チュートリアルも最初から最後まで正常に進行するようになりました。

jsdomで実際のクリック操作を再現したヘッドレステスト（25件）で、初期デッキが正しく20枚・10種類で構成されること、チュートリアルの全7ステップ（カードタブ→カード追加→バトルタブ→ステージ選択→モンスター選択→召喚→ターン終了）が最後まで正常に完了すること、既存のガチャ排出ロジックに影響がないことを確認済みです。
